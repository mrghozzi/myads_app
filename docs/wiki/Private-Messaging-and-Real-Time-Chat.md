# Private Messaging & Real-Time Chat

The MYADS Mobile App includes a complete 1-on-1 private messaging module (`/messages`) supporting conversation lists, chat bubbles, media attachments, and real-time updates.

---

## 1. Navigation & Screen Flow

```
┌────────────────────────────────────────────────────────┐
│  MessagesListScreen (/messages)                        │
│  - Conversation search                                 │
│  - Recent conversations with unread badges             │
│  - Online presence indicators                          │
└───────────────────────────┬────────────────────────────┘
                            │ Taps conversation
┌───────────────────────────▼────────────────────────────┐
│  ChatScreen (/messages/chat/:routeKey)                 │
│  - Encrypted conversation thread                       │
│  - Chat bubbles (outgoing vs incoming)                 │
│  - Real-time polling updates                           │
│  - Message composer & media attachment picker          │
└────────────────────────────────────────────────────────┘
```

---

## 2. Real-Time Polling Engine (`/api/messages/updates`)

While the chat screen is in the foreground:
* A lightweight periodic timer polls `/api/messages/updates?last_id=<id>` every **3 seconds**.
* Only new messages since `last_id` are returned, keeping payload sizes under a few hundred bytes.
* When the user navigates away or the app enters the background, the polling timer is immediately cancelled to conserve battery and mobile data.

---

## 3. End-to-End Route Key Routing

Conversations are identified by an encrypted `route_key` generated by the backend:
* Prevents leaking participant IDs in navigation URLs.
* GoRouter route path: `/messages/chat/:routeKey`.
* If a route key is temporarily unavailable (e.g. initiating a new chat from a member's profile), the app transparently passes `?username=<name>` as a fallback, which the backend automatically resolves into an existing or new conversation thread.
